# Ghost Run+: Kiro integration

The hooks, the MCP server, and the power, and the three ways to use them in Kiro. Part of [Ghost Run+](../README.md).

## Use it in your Kiro

- **Start from this template** (enforcement): clone the repository, run `corepack pnpm install` and `corepack pnpm -r build`, build the box image (`corepack pnpm --filter @ghost-run/ghost-runner box:build`), open the folder in Kiro and trust it, run `corepack pnpm gate:on`, and start a new session. `gate:on` sets `enabled` to `true` in both entries of `.kiro/hooks/ghost-gate.json` and in `.kiro/hooks/docker-warmup.json`, and changes nothing else. `corepack pnpm gate:off` switches it off again and `corepack pnpm gate:status` prints the state. The committed hook files stay disabled. The hook-file tests (`hook-files.test.mjs`, `docker-warmup.test.mjs`) check the committed version (`git show HEAD:<file>`, or the file on disk when git is not available), so they also pass in a working tree where the gate is on. They separately check that the files on disk are valid and differ from the committed ones only in `enabled`. The gate depends on the workspace packages (`core`, `ghost-runner`, `wards-config`), so copying `integrations/kiro-hook/` into another project does not build; use the installer in the next bullet, which copies a bundle.
- **In an existing project, with enforcement**: run the installer from this repository, `node <repository>/integrations/power/install-gate.mjs --project <your project>` (without `--project` it uses the current folder). It copies a self-contained gate bundle and the box sources to `<project>/.kiro/ghost-run/`, writes `.kiro/hooks/ghost-gate.json` and `docker-warmup.json` **enabled** (running the installer is the opt-in), writes a default `wards.yaml` only when the project has none (with a commented `trusted_commands` example), and adds `.ghost-run/` to `.gitignore`. The gate needs only Node 20 or later and no `node_modules`. Build the box image once with `node .kiro/ghost-run/box/build.mjs` (needs Docker); without Docker the gate falls back to static analysis (Plan B) and asks. The installer overwrites no existing file without `--force`, lists what it wrote in `.kiro/ghost-run/manifest.json`, and `--uninstall` removes exactly those files. To switch the gate off, set `enabled` to `false` in the two hook files. See [integrations/power/README.md](../integrations/power/README.md).
- **In an existing project, advisory only**: install the power for the tools and the skill. In the Kiro Powers panel choose Add Custom Power and Import from folder, or run `kiro-cli powers install <repository>/integrations/power`. Nothing enforces a verdict there. See [integrations/power/README.md](../integrations/power/README.md) for the workspace root rule, the default wards, and the box image.
- **MCP server in this workspace.** `.kiro/settings/mcp.json` registers the `ghost-run` server from `integrations/mcp/bin/ghost-run-mcp.mjs` and ships with `"disabled": true`. To switch it on, run `corepack pnpm -r build`, set `disabled` to `false`, and reload the MCP servers in Kiro. `gate:on` does not switch it. See [integrations/mcp/README.md](../integrations/mcp/README.md#use-it-in-kiro-from-this-repository).
- Full rehearsal needs Docker and the box image (`corepack pnpm --filter @ghost-run/ghost-runner box:build`).
- In a non-interactive Kiro CLI run with `--trust-all-tools`, Kiro answers an `ask` itself, so a warned command runs. A blocked command is still blocked. For unattended runs use `--trust-tools=@builtin` or narrower: there an `ask` gets no answer and the call is refused. See [integrations/kiro-hook/README.md](../integrations/kiro-hook/README.md).
- **Package-manager commands cannot be rehearsed faithfully.** The Copy excludes `node_modules` (`DEFAULT_EXCLUDE_DIRS` in `ghost-runner/src/config.ts`) and the box runs with `--network none`. In the box, `corepack` tries to download the pinned pnpm from registry.npmjs.org, the recorder sees a network attempt, and the gate asks. In the first gated Kiro CLI sessions, most of the asks left after the fixes of 2026-11-25 came from such commands, for example `corepack pnpm test`.
- Without Docker the gate falls back to static analysis (Plan B) and asks for human approval. It does not claim P1 isolation in that mode.
- Docker Desktop's Resource Saver can stop its VM when idle. The gate retries once with a longer deadline, so a sleeping Docker is not mistaken for a missing one. See [integrations/kiro-hook/README.md](../integrations/kiro-hook/README.md).

## Kiro integration

Ghost Run+ plugs into Kiro (IDE and CLI) with six hooks, one MCP server, and one power. Details, claims, and limits are in the READMEs of each part:

- [`integrations/kiro-hook/`](../integrations/kiro-hook/README.md): the hooks `ghost-gate` (Pre Tool Use), `ghost-log` (Post Tool Use), `contract-pbt`, `world-scaffold`, `blacklight-steering`, and `docker-warmup` (Pre Tool Use for `shell`; wakes Docker Desktop before the gate's first check). The note on [cross-call exfiltration](../integrations/kiro-hook/docs/cross-call-exfiltration.md) states what the records can and cannot do.
- **Seance link.** The `Seance:` link in a block or ask message opens a local read-only page for that grave (command, candle, wards with numbers, diff, claims, red thread). The gate starts the viewer in the background on `localhost:5317` after a grave; start it by hand with `corepack pnpm --filter @ghost-run/kiro-hook seance`, and switch the auto-start off with `GHOST_RUN_SEANCE_AUTOSTART=0`. See [integrations/kiro-hook/README.md](../integrations/kiro-hook/README.md#seance-link).
- [`integrations/mcp/`](../integrations/mcp/README.md): the advisory MCP server `ghost-run` with the tools `ghost_run`, `ghost_diff`, `ghost_trace`, `wards_check`, and `blacklight`.
- [`integrations/power/`](../integrations/power/README.md): the Kiro power (plugin file, skill, and a bundled server). It gives the advisory tools and the skill, not the enforcing gate.

- **P1 is claimed per run, never as a property of a hook.** The gate and `ghost_run` repeat the flags `p1Claimed`, `p5Claimed`, and `p6Claimed` of the run they report, and claim nothing when the flag is `false`.
- **Plan B.** Without Docker and the built box image the run is static analysis only. P1, P5, and P6 are not claimed, the message says `P1 isolation is NOT guaranteed`, and the verdict is at least `warn`.
- **A seatbelt, not full isolation.** A `pass` is not an approval of the real command, text analysis does not catch every injection, and the hooks are not tamper-resistant against a process with the developer's privileges. P6 holds within one tool call only.
- **State.** Every hook file in `.kiro/hooks/` is committed with `enabled: false`, and so is the MCP entry in `.kiro/settings/mcp.json`. The probe and experiment hook files are in `integrations/kiro-hook/experiments/`, not in `.kiro/hooks/`. The gate is switched on by a human after a checklist. Facts that were measured in the Kiro CLI and not in the IDE say so where they are stated.
- Supported on macOS and Linux. Windows is unverified.
